1. OBJECTIVE

To strengthen the DVWA File Upload functionality against unrestricted
file upload, malicious file extensions, MIME-type spoofing, invalid
image content, and unsafe uploaded filenames.

2. ORIGINAL WEAKNESSES IDENTIFIED

The original Impossible-level implementation included several useful
checks but had limitations:

- Relied partly on the original filename extension.
- Relied on the browser-provided MIME type.
- Did not independently verify the uploaded file using PHP Fileinfo.
- Did not enforce a strict image-dimension and pixel-count limit.
- Used temporary image processing that required additional safeguards.
- Used an image-destruction operation that produced a PHP 8.5
  deprecation warning when the image was invalid.

3. REMEDIATION IMPLEMENTED

The hardened handler was implemented in:

vulnerabilities/upload/source/impossible.php

The replacement introduces:

- POST upload handling and CSRF token validation.
- Validation of the PHP upload error status.
- Verification using is_uploaded_file().
- Server-side file-size verification, with a 100,000-byte limit.
- Strict JPEG and PNG extension allowlisting.
- MIME detection using PHP Fileinfo.
- Independent image-structure validation using getimagesize().
- Image dimension and total pixel-count restrictions.
- JPEG/PNG format consistency checks.
- Image decoding using the appropriate GD decoder.
- Random 16-byte filenames generated with random_bytes().
- Re-encoding of accepted images using GD.
- Temporary output creation within the destination directory.
- File permission restriction to 0644.
- Atomic rename into the upload directory.
- HTML output encoding for the generated filename.
- Generic user-facing rejection messages and server-side error logging.
- Temporary-file cleanup after processing.

The handler does not trust the original browser filename as the
stored filename.
