SQL INJECTION (BLIND) — HARDENED REMEDIATION REPORT
Student ID: 28212
Environment: Separate hardened DVWA Docker environment
Security level: Impossible

1. IDENTIFIED WEAKNESS
The original Impossible-level handler accepted user-controlled input and relied on numeric conversion before querying the database. The remediation strengthens input validation and uses parameterised database queries.

2. REMEDIATION IMPLEMENTED
- Required the submitted ID to be a non-empty string containing decimal digits only.
- Validated the integer using FILTER_VALIDATE_INT before conversion.
- Used a PDO prepared statement and PDO::PARAM_INT for MySQL.
- Used a prepared SQLite statement with SQLITE3_INTEGER for SQLite.
- Queried for a matching record using a parameter rather than concatenating user input into SQL.
- Preserved CSRF token validation and session-token regeneration.
- Returned a normal existence result or a missing-record response without exposing database query details.

3. VERIFICATION
The live hardened PHP file passed PHP syntax validation.
The legitimate lookup test using ID 1 returned:
"User ID exists in the database."
The SQL injection test using:
1 OR 1=1
was rejected as a valid record lookup and returned:
"User ID is MISSING from the database."
